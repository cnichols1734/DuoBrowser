Full-width rendering and automatic fitting were enabled, except for explicit original-layout comparisons on Amazon and Google. Primary pose: closed outer display. This is a manual compatibility smoke test, not an all-sites pass or an automated end-to-end suite. Width and collision findings below are visual; this run did not inject geometry diagnostics, collect DOM content, measure frame rate, or measure exact site widths. Existing synthetic tests and native fixture measurements are recorded separately in VALIDATION.md. No application code changed during this test run.

## Prioritized follow-up

1. **Protect controls from the camera.** Full-width rendering alone leaves controls in the reserved region. Walmart's search Cancel and the shopping-header/cart areas are concrete fixtures to reproduce. Use runtime geometry and reversible group/control adjustments; do not add a permanent rail or host-specific offsets.
2. **Handle site bottom UI under browser chrome.** Reddit's bottom sheet, Instagram's bottom navigation, Walmart's app prompt, and the NY Times gate show different forms of overlap. `BrowserView` currently adds native scroll content inset, while the toolbar floats over the web view. That does not establish protection for arbitrary site-fixed UI. Design and verify a general policy that preserves page dimensions, taps, focus, and smooth toolbar transitions.
3. **Broaden gutter detection conservatively.** Google results are a confirmed unsupported case because original and automatic modes look alike. Facebook and Instagram need geometry diagnosis before attributing their left-weighted layouts to safe-area padding. Do not remove intentional max-width or spacing based only on appearance.
4. **Keep browser link actions inside the browser where appropriate.** Reproduce the Google native context-menu Open Link path. Source inspection found no installed `WKUIDelegate` or custom web-link context menu; the existing navigation delegate handles missing target frames but does not cover every native menu action. Determine the public-API fix and test both ordinary taps and native link previews.

These are open findings, not fixes delivered by this test pass. The run supports continuing with a general collision/overlay engine before optional AI selection; it does not establish that AI is needed for these cases.

## Coverage limits and ending state

- All eight requested sites were loaded in the simulator. No CAPTCHA or access-security warning was manually bypassed.
- Logged-out sessions only. Facebook/Instagram authenticated flows, Google account avatar, Amazon account menus, NY Times subscription access, and Walmart saved-account flows need a separate signed-in test.
- Search was exercised with the simulator's hardware-keyboard input and visible input accessory controls. The software-keyboard, native pinch, rotation, partially folded poses, VoiceOver, larger text, Reduce Motion, long-running infinite scroll, energy, and physical hardware matrix remain open.
- No claim that every visible full-width site was modified by the adapter: a site can already be full width. Adapter application state was not instrumented in this run.
- No screenshots, browsing tokens, account information, or page-content dumps were saved as deliverables. Only summarized outcomes and public test queries are recorded here.
- Left DuoBrowser QA on Walmart's empty cart, folded closed, with automatic fitting enabled. The user's separate iPhone Duo simulator was not used.
