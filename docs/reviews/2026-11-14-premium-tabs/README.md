Actual simulator touch inspection also verified Page options → New Tab → Tabs and overview New Tab → Tabs without restarting. ## Implemented behavior

- Search Tabs is visible at the top of the overview. Workspace/private identity and the tab count remain explicit.
- The existing native thumbnail grid is preserved. A remembered List option provides a compact alternative; VoiceOver and accessibility text sizes continue to use a list.
- Select mode supports multi-selection, filtered Select/Deselect All, confirmed batch closure and normal-workspace moves. Selection is cleared on profile/workspace changes and pruned when tabs disappear. Grid close swipes are disabled while selecting.
- List selection mode exposes native drag reordering. Grid/list context menus provide Move Earlier/Later. Reordering preserves pinned-first order, model identity, live WKWebViews and selection; stale, incomplete and duplicate order snapshots are rejected.
- Failed normal-session writes roll reordering and batch moves back before reporting failure. The overview shows a short save error and keeps a failed move's selection available for retry. Synthetic primary-write failure injection verifies rollback and the unchanged durable archive.
- A selected-tab move commits its replacement selection in the same archive write as workspace membership. The replacement is not selected or activated until that write succeeds. A later debounced save failure therefore cannot restore the moved tab's destination workspace instead of the source workspace left visible after the move. The optional archive selection override rejects IDs outside the normal session and leaves ordinary saves unchanged.
- Swiping the address capsule follows the finger with an adjacent tab preview. A validated release selects the existing neighbor in the same workspace/private profile. Cancellation returns the same live page. Profile/selection changes, backgrounding, presentation and changed view bounds cancel temporary presentation. No background page is activated merely to display a preview.
- The same attached-window and modal eligibility checks apply during movement, on release and when the commit animation completes. The hosted content must remain attached to the container's window, and no new presentation may intervene. A late source dialog or window loss restores the current live page and clears swipe visuals without cancelling that dialog or selecting its neighbor. Native start pages remain eligible without requiring a loaded WebKit page. Every animation completion position clears temporary motion; only a completed, still-eligible commit changes tabs.
- A new swipe can catch an active snap-back at its current presentation position rather than being ignored or snapping to a new origin. The first native integration run exposed this boundary: model transforms already held their final values while the cancellation animator was still active. The production gesture now interrupts that animator and preserves its current offset for the new drag's presentation; an explicit native regression checks interruption, continuity and commitment.
- Reversing direction during a caught snap-back chooses the adjacent tab from the fresh gesture's direction. The old page offset is visual context only and cannot satisfy a new gesture's commitment threshold. A temporary in-memory native preview keeps the returning side filled while the new neighbor enters from the other side; it is removed on completion/cancellation. Native regressions cover opposite-direction continuity, previous-tab commitment, tiny-gesture cancellation, live draft retention and Reduce Motion.
- Reduce Motion uses opacity rather than a moving page. Existing accessible Previous/Next Tab actions remain available. List mode uses a cross-dissolve when entering/leaving the overview because it has no thumbnail zoom source.
- Owner device feedback identified New Tab → Tabs becoming unresponsive until relaunch. The presenter now chooses a cross-dissolve when the live tab changed inside an already-presented browser, or when the selected tab has no valid rendered thumbnail. It never requests a matched zoom from a missing card. UIKit presentation state and lifecycle notifications drive reconciliation; there is no completion-only Boolean latch, and repeated Tabs requests can retry reconciliation.

## Remaining acceptance

The native check drives production gesture events and UIKit presentation directly; actual finger recognition and the visual feel of swiping require simulator interaction and owner device testing. Physical touch, energy, long-running many-tab behavior and spoken VoiceOver acceptance are not established by source parsing or synthetic assertions. Cold restoration still restores addresses and best-effort reading positions, not arbitrary page forms or full navigation histories. Explicitly closing multiple tabs discards their unsaved website input after confirmation; Recently Closed remains address-based recovery.

## Native blank-page fixture readiness

The blank-to-blank native swipe fixture now waits for the intended toolbar as the sole mounted gesture owner, in addition to the attached-window and modal checks. Debug-only per-instance lifecycle observations capture each toolbar’s immutable browser ID, and report disappearance only after its existing cancellation has run. This prevents the fixture from injecting a new gesture before SwiftUI replaces the previous toolbar. Both 10-second interaction deadlines and the final selection assertion are unchanged; Release behavior and assertion counts are unchanged. Failure output includes synthetic owner/window/presentation state.
