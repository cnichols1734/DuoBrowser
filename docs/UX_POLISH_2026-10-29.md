# Search, native previews and protection polish

This revision responds to the owner's rejection of the initial search sheet and request for an Apple-style link preview. It updates PR #5 and carries the reviewed camera fixes from PR #4. Neither PR is merged or released by this work.

## Interaction changes

- Search is a content-sized command overlay above the keyboard, with a softly blurred page behind it. It removes the former sheet, grabber, Search heading, quick-action pills and oversized submit button. A single field and Cancel action sit beneath a few destination rows. Results show host/path metadata and suppress duplicate library fragment variants while preserving distinct open tabs. The field has a bounded scaled height; the available viewport controls how many results fit. Typing remains local until explicit submission.
- Long-press preview uses WebKit's context-menu preview provider and UIKit's commit animator. The temporary page is owned separately until promotion; dismissing, backgrounding or closing the source releases it. The same live web view is adopted when committed. Stale animation completions cannot promote a replacement preview. This replaces the former full-screen Peek sheet.
- Website Protection is a dedicated page-options destination. It distinguishes preparing, enabled, disabled, unavailable and no-website states. A site switch explains that changes reload the page; the exception list provides a Protect action. Private exceptions remain scoped to the private session. The UI describes the bundled 19-service baseline and does not invent request counts or claim comprehensive blocking.
- Tab and library empty states distinguish an empty collection from a search with no matches. Library rows have consistent title/host hierarchy and touch targets. Existing bottom glass controls, camera geometry and native typography remain intact.

The design follows the owner’s requested compact, Arc-inspired search direction. The preview uses Apple's public [WebKit context-menu commit API](https://developer.apple.com/documentation/webkit/wkuidelegate/webview(_:contextmenuforelement:willcommitwithanimator:)); it does not reproduce private Safari implementation details.
